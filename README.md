# Day 4 — Incident Response Automation from Day 3 Anomaly Results

This is the connected follow-on to Day 3. It does **not** start from a separately hand-written incident JSON file. It consumes the `anomaly_comparison.csv` generated by Day 3 and turns flagged observations into incident triage records and GitHub Issues.

## Day 3 → Day 4 connection

Day 3 generates `data/processed/anomaly_comparison.csv`. Copy that file to this project's `data/day3/anomaly_comparison.csv`. The starter pack already includes the matching sample output from the supplied Day 3 dataset so you can test immediately. If you have your own Day 3 output, replace the bundled CSV with it before running the lab.

The Day 4 script identifies rows where `rule_anomaly == 1` or `ml_anomaly == 1`, classifies them using transparent training rules, and generates `outputs/incident_events.json` **from the CSV** plus `outputs/day4_incident_report.md`. The JSON is generated output, not a manually maintained input.

## Tools
- Python 3.10+ recommended; standard library only. No pip dependencies required.
- GitHub repository with Actions enabled.
- No cloud account or production credentials.

## Local run (from this project root)
```bash
python scripts/validate_day3_output.py
python -m unittest discover -s tests -v
python scripts/triage_from_day3.py
python scripts/simulate_remediation.py
```

Expected output with the supplied Day 3 sample: 20 rows, 3 flagged rows, classified as HIGH, CRITICAL, HIGH. These are training classifications only. Different Day 3 data can produce different counts and classifications.

## GitHub setup
1. Create a new empty, private repository named `aiops-day4-day3-incident-lab` (do not initialize with a README).
2. Open a terminal at the folder containing this README.
3. Run:
```bash
git init -b main
git add .
git commit -m "Add Day 4 incident automation using Day 3 results"
git remote add origin https://github.com/YOUR-USERNAME/aiops-day4-day3-incident-lab.git
git push -u origin main
```
Replace the sample URL with the URL of your empty repository. Do not force-push if setup differs; resolve repository setup with the trainer.

## Workflows
- `Validate Day 3 Anomaly Output` runs on pushes/PRs, validates the CSV, runs unit tests, generates a preview, and uploads an artifact. It needs only `contents: read`.
- `Day 4 Incident Response from Day 3 Output` is manually triggered from Actions. It creates one GitHub Issue per HIGH/CRITICAL flagged observation and avoids duplicate Issues with the same title. It requests `issues: write` for this action. An optional input writes a remediation simulation report only.

The workflow does not contact, restart, scale, delete, or modify a real system. If GitHub Actions cannot write Issues due to repository/organization policy, ask the administrator; do not use a personal access token or weaken policy.
